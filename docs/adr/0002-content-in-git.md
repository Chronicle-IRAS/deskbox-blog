# ADR 0002：内容存放在 Git，使用 Markdown/MDX

- **状态：** 提议（设计基线，待作者确认）
- **日期：** 2026-10-18
- **决策者：** 项目作者
- **关联：** [架构设计](../architecture.md) · [视觉设计](../design.md)

## 背景

个人博客的内容需要长期保存、可迁移、可审查。可选方案：

1. Git 仓库中的 Markdown/MDX（无 CMS）。
2. Headless CMS（Contentful、Sanity、Strapi 等）。
3. 数据库 + 自建后台。
4. 笔记软件导出（Obsidian、Notion）再同步。

作者需要：写作时不被后台打断；文章可 diff、可回滚；图片与正文一起迁移；不依赖第三方服务存活。

## 决策

**Git 仓库是唯一内容源。** 文章以目录为单位存放：

```text
src/content/blog/2026/10/<slug>/
├── index.md | index.mdx
├── cover.jpg
└── diagram.png
```

- Frontmatter 使用 Zod schema 校验；`slug` 显式声明并与 URL 一致。
- 标签使用集中注册表（`src/data/tags.ts`），构建期拒绝未注册标签。
- 草稿与未来日期在构建时过滤；构建产物不包含。
- 图片与文章同目录；封面通过 `astro:assets` 优化，正文图片在 MDX 中用 `<Image />`。
- 原型阶段只在本地开发/构建；发布流程与远程仓库策略在上线阶段设计。

## 后果

### 正面

- 纯文本、可移植；不依赖 CMS 存活或导出格式。
- 版本历史、diff、code review、回滚天然可用。
- 本地写作与预览无需网络/后台。
- 内容与代码共用本地检查；坏 frontmatter 在构建期失败。
- 无数据库备份问题；原型阶段内容在本地 Git 工作区。

### 负面 / 约束

- 非技术作者需要学习 Git/Markdown；本项目为单人博客，可接受。
- 没有可视化编辑器；图片需手动放入目录。
- 标签注册表需要手动维护；新增标签多一步。
- 评论不在站内存储；原型不做评论，后续再评估 Giscus/GitHub Discussions。
- 草稿只在本地开发中预览；原型不涉及预览部署。

## 备选方案

| 方案 | 放弃原因 |
|---|---|
| Headless CMS | 引入外部服务、API、内容锁定；个人博客不需要多人协作/可视化编辑 |
| 数据库 + 自建后台 | 需要服务器、认证、备份、安全维护；与静态架构冲突 |
| 笔记软件导出 | 格式不可控、图片路径易断、CI 难校验；可作为写作草稿，但发布源仍是 Git |

## 验证

- 新增一篇文章只需新增目录 + frontmatter，无需改代码。
- 未知标签、缺 `coverAlt`、`updatedDate < pubDate` 会让构建失败并指出字段。
- 删除/重命名文章后，列表、标签页与 P1 的 RSS/sitemap 同步更新。
- `npm ci` + `npm run build` 可在无外部 CMS 的情况下完整重建原型。
