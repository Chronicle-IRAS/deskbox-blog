# ADR 0001：静态站点 + Astro

- **状态：** 提议（设计基线，待作者确认）
- **日期：** 2026-10-18
- **决策者：** 项目作者
- **关联：** [架构设计](../architecture.md)

## 背景

个人博客的主要负载是“读文章”：内容更新频率低、读者分布广、没有登录/交易/实时数据需求。需要同时满足：

- 写作与发布简单，不维护服务器、数据库、后台。
- 首屏快，移动端体验好，SEO 友好。
- 内容结构有类型约束，坏数据在构建期失败。
- 未来可迁移，不被托管平台锁定。

候选方案：Astro、Next.js（App Router）、Hugo、纯手写 HTML、WordPress。

## 决策

采用 **Astro 7.x + TypeScript strict**，构建期生成静态站点（SSG）。运行时没有 Node 服务、数据库或认证；构建产物是 `dist/` 下的静态文件。

关键约束：

- `output: 'static'`（默认），不使用 SSR/动态路由。
- 内容使用 Astro Content Collections + Zod 校验。
- Markdown/MDX 构建期渲染，Shiki 构建期高亮。
- 默认零客户端框架；交互仅主题切换、代码复制、TOC 高亮；搜索页脚本在 P1 按需加载。
- 搜索使用构建后 Pagefind 索引，不引入搜索服务（P1）。
- **原型阶段不选择部署平台**；只保证 `npm run dev` 与 `npm run build` 可用，`dist/` 保持纯静态，部署后续单独决策。

## 后果

### 正面

- 无服务器/数据库运维；攻击面小；成本低。
- HTML 直达，LCP/CLS 容易达标；无首屏框架 hydration。
- 内容与代码同仓库，PR 可预览、可回滚。
- Astro 的岛屿模型允许未来局部加入交互，而不必重写整站。
- 静态产物可迁移，避免托管锁定。

### 负面 / 约束

- 没有运行期动态能力：评论、分析等必须使用构建期或第三方方案；这些不在原型范围。
- 搜索依赖构建后索引（Pagefind），P1 才有；P0 用归档/列表兜底。
- 构建时间随文章数量增长；个人博客规模内可接受。
- 发布、预览、回滚与定时构建属于上线阶段，原型不处理。

## 备选方案

| 方案 | 放弃原因 |
|---|---|
| Next.js App Router | 引入 Node 运行时、缓存、部署复杂度；个人博客用不到 SSR/Server Actions |
| Hugo | 构建快，但模板类型安全弱；内容校验与图片处理不如 Astro 直接 |
| 纯手写 HTML | 路由、分页、RSS、sitemap、图片优化都要手写，长期维护成本高 |
| WordPress | 需要服务器/数据库/插件维护；与 Git 内容流冲突 |

## 验证

- `npm run dev` 可本地浏览所有 P0 路由。
- `npm run build` 产出静态 `dist/`，不依赖 Node 运行时。
- 用本地静态服务器打开 `dist/`；禁用 JS 仍可阅读文章与导航。
- 原型不验证部署、域名或 CDN。
