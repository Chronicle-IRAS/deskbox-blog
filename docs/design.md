# 个人博客 · 视觉与交互设计

**状态：** 原型设计 v2  
**日期：** 2026-10-18  
**设计系统：** [DeskBox Blog Design System](../design-system/deskbox-blog/MASTER.md)（颜色、字体、间距、组件规格以该文件为准）  
**架构：** [架构设计](./architecture.md) · [原型实施计划](./prototype-plan.md)  
**并行实施：** [Claude Code P0](./plans/claude-code-p0.md) · [omp P0](./plans/omp-p0.md)

**原型范围：** P0 先做首页、文章列表、文章页、About、404、主题切换、响应式、TOC、代码复制；P1 再加标签、归档、分页、搜索、RSS。  
**不在原型内：** 部署、域名、CI/CD、评论、分析、多语言、OG 图生成。

---

## 1. 设计方向

**关键词：** 瑞士编辑风 · 内容优先 · 单色 + 一个信号色 · 克制的网格 · 纸感浅色 / 墨感深色

这是一个“长期写作的个人博客”，不是产品落地页。设计不追求第一眼惊艳，而追求：

- 打开文章就能读，不被 Hero、弹窗、推荐位打断。
- 层级清楚：标题、日期、摘要、正文、目录、标签各自有稳定位置。
- 视觉记忆点来自排版与一个粉色信号，而不是插画、渐变或卡片阴影。
- 浅色像纸，深色像墨；两种模式都安静。

**参考气质：** 国际主义平面设计、编辑杂志、个人技术博客的“文章列表 + 长文”传统。  
**明确避免：** SaaS 落地页、玻璃拟态、渐变 Hero、滚动叙事、卡片瀑布流、自动播放。

---

## 2. 读者与任务

| 读者 | 场景 | 任务 | 设计回应 |
|---|---|---|---|
| 搜索引擎/社交来的新读者 | 手机、单篇 | 快速判断“值不值得读”，读完 | 清晰标题/摘要/阅读时间；正文 42rem；无干扰 |
| RSS 订阅者（P1） | 阅读器 | 读全文 | RSS 全文；文章内相对链接转绝对 |
| 回访读者 | 桌面/手机 | 找新文章、按主题找 | 首页最近文章；标签/归档（P1）；搜索（P1） |
| 作者 | 本地 | 写、预览、检查 | Markdown/MDX；构建期校验；`npm run dev` / `npm run build` |

**核心阅读路径：** 首页 → 文章 → 标签/归档 → 搜索（P1）。  
**核心写作路径：** 新建目录 → 写 frontmatter → `npm run dev` 预览 → 本地构建检查。

## 3. 信息架构与导航

```text
P0
├── /                    首页
├── /blog/               全部文章（第 1 页）
├── /blog/<slug>/        文章
├── /about/              关于
└── /404.html

P1 追加
├── /blog/page/2/        分页
├── /tags/               标签索引
├── /tags/<tag-slug>/    标签文章
├── /archive/            按年归档
├── /search/             搜索
├── /rss.xml
└── /sitemap-index.xml
```

**主导航（Header）**
- P0：文章 · 关于 + 主题切换。
- P1：文章 · 标签 · 归档 · 关于 · 搜索 + 主题切换。

**Footer：** P0 为 GitHub · Email · 版权；P1 加 RSS。  
**不做：** 侧边栏、浮动目录按钮、返回顶部悬浮球、社交分享条。

导航原则：

- 当前页用 `aria-current="page"` + 2px 下划线；不改变字号/字重。
- 移动端使用 `<details>` 下拉菜单，不依赖 JS；链接点击后自然跳转关闭。
- 搜索（P1）是独立页面，不用全屏弹窗；避免焦点陷阱与额外 JS。
- 页脚链接不重复主导航；只放订阅/联系/版权。

### 4.2 文章列表 `/blog/`

**目标：** 扫读标题，快速找到感兴趣的内容。

**结构**

1. 页面标题“文章”+ 总数（如“12 篇”）。
2. 标签筛选行：`全部` + 标签链接（服务端生成，不用 JS）。
3. 文章列表：每行左侧日期（96px），右侧标题 + 摘要 + 标签/阅读时间。
4. 分页：上一页 / 页码 / 下一页；第 1 页链接到 `/blog/`。
5. 空状态：没有文章时说明并链接到首页。

**线框**

```text
文章  12 篇

全部   前端   后端   工程实践   阅读   生活
────────────────────────────────────────────────────────────
2026.10.18   文章标题                              #前端  8 分钟
             一句话摘要，最多两行。
────────────────────────────────────────────────────────────
2026.10.12   文章标题                              #阅读  5 分钟
             一句话摘要，最多两行。
────────────────────────────────────────────────────────────
...

                          上一页   1  2  3   下一页
```

**规则**

- P0 展示全部 12 篇；P1 改为每页 10 篇并出现分页。
- 按 `pubDate` 降序，同日按 slug 稳定排序。
- 摘要最多 2 行（`line-clamp: 2`），不截断标题。
- 标签筛选是链接，不引入客户端筛选状态；URL 可分享。
- 日期列在移动端折叠为标题上方的一行元信息。
- 列表行悬停仅改变背景/边框，不位移。

### 4.3 文章页 `/blog/<slug>/`

**目标：** 最舒适的长时间阅读；同时提供目录、标签与下一步。

**结构**

1. Header。
2. 文章头部（最大 42rem，左对齐）：
   - 元信息：发布日期 · 阅读时间 · 标签。
   - H1 标题（`text-wrap: balance`）。
   - 可选摘要/导语（`description`，比正文稍大，`--fg-muted`）。
   - 可选封面（16:9，带 `coverAlt`）。
3. 正文 + 目录：
   - 桌面 ≥1024px：正文 42rem，右侧 220px sticky 目录。
   - 移动端：标题下方折叠 `<details>` “本文目录”。
4. 正文结束：系列导航（如有）、上一篇/下一篇。
5. 评论（可选，点击加载）。
6. Footer。

**桌面线框**

```text
┌──────────────────────────────────────────────────────────────────────┐
│ DeskBox                      文章   标签   归档   关于   搜索   ◐   │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  2026.10.18 · 约 8 分钟 · #前端  #工程实践                            │
│  文章标题最多两行，但允许自然换行                                      │
│  一句话摘要，可选。                                                   │
│                                                                      │
│  ┌────────────────────────────────────┐    ┌──────────────────────┐  │
│  │ 正文                               │    │ 本文目录             │  │
│  │                                    │    │ 01  背景             │  │
│  │ H2 小节标题                        │    │ 02  方案             │  │
│  │ 段落...                            │    │ 03  结果             │  │
│  │                                    │    │ 04  复盘             │  │
│  │ ┌────────────────────────────────┐ │    │                      │  │
│  │ │ code block              [复制] │ │    │                      │  │
│  │ └────────────────────────────────┘ │    │                      │  │
│  │                                    │    │                      │  │
│  └────────────────────────────────────┘    └──────────────────────┘  │
│                                                                      │
│  ← 上一篇：标题                          下一篇：标题 →               │
│                                                                      │
│  ── 讨论 ──────────────────────────────────────────────────────────  │
│  [ 加载评论 ]  评论由 GitHub Discussions 提供，点击后加载。           │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│ © 2026 DeskBox · RSS · GitHub · 由 Astro 驱动                        │
└──────────────────────────────────────────────────────────────────────┘
```

**文章头部规则**

- 标题与正文同宽（42rem），不跨到目录列。
- 日期用 `<time datetime="YYYY-MM-DD">`；显示 `2026.10.18`。
- 有更新时显示“更新于 2026.10.20”，不替换原发布日期。
- 阅读时间估算：中文 300 字/分钟 + 英文 200 词/分钟，向上取整。
- 标签最多 3 个；每个标签是链接。
- 封面图 `loading="eager"` + `fetchpriority="high"`（若在首屏）；否则懒加载。
- 摘要 `description` 可选显示；不重复标题。

**正文规则**

- H2/H3 自动生成锚点；标题悬停显示 `#` 链接（可选，键盘可达）。
- 段落 17px / 1.85；段间距 1.25em；中文不首行缩进。
- 引用、提示框：左侧 2px 粉色边框；不使用大面积彩色背景。
- 代码块：语言标签 + 复制按钮；横向滚动；键盘可聚焦。
- 表格：外层可横向滚动；表头加粗；数字右对齐可选。
- 图片：宽度不超过正文；`figcaption` 说明来源/内容；不放大图查看（v1）。
- 脚注使用 GFM 脚注；文末自动生成。
- 外链：12px 箭头图标 + `rel="noopener noreferrer"`；新窗口打开需谨慎（v1 同窗口，避免意外）。
- 深层链接：标题 `scroll-margin-top: 80px`，不被粘性 Header 遮挡。

**目录规则**

- 只收 H2/H3；H4 不进入。
- 少于 3 个标题时不显示目录。
- 桌面 sticky `top: 96px`；当前项用 IntersectionObserver 高亮（渐进增强；无 JS 时目录仍可点击）。
- 移动端 `<details>` 默认关闭；展开后不吸顶。

**文末规则**

- 系列文章：显示同系列其他文章与顺序。
- 上一篇/下一篇：按发布时间；没有则显示“没有更早/更新的文章”。
- 评论：默认只显示“加载评论”按钮；未配置时整段隐藏。
- 不在文末放“相关文章”算法推荐；用标签/系列替代。

### 4.4 标签 `/tags/` 与 `/tags/<tag>/`（P1）

**标签索引**

```text
标签

前端        4 篇    浏览器、框架与工程化
后端        2 篇    服务端、数据与基础设施
工程实践    3 篇    协作、测试与交付
阅读        5 篇    书与长文笔记
生活        1 篇    写作之外
```

- 按注册表顺序展示（作者可控），不按数量/拼音自动排序。
- 每行：标签名（链接）+ 数量 + 一句说明。
- 移动端两行布局：名称/数量一行，说明一行。

**标签详情**

- 标题 `#前端`，副标题为标签说明与数量。
- 复用文章列表组件；v1 不分页，展示该标签下全部文章（个人博客规模足够；超过 50 篇再引入 `/tags/<tag>/page/[page]/`）。
- 标签页不设 `noindex`；canonical 指向自身。
- 空标签不生成页面（注册表可保留说明，但无文章时不进入 sitemap）。

### 4.5 归档 `/archive/`（P1）

```text
归档

2026  (5)
  10.18   文章标题                              #前端
  10.12   文章标题                              #阅读
2025  (12)
  12.30   文章标题                              #生活
  ...
```

- 按年份分组，组内按日期降序。
- 行内只保留日期、标题、标签；摘要省略。
- 年份作为 H2；不提供年份筛选 JS。
- 文章很多时仍保持单页（个人博客规模足够）；超过 200 篇再考虑分页。

### 4.6 关于 `/about/`

- 标题“关于”。
- 可选头像：96×96，方形 6px 圆角（不用圆形，保持瑞士网格感）。
- 2–5 段自我介绍：是谁、做什么、写什么、如何联系。
- 社交链接：GitHub / Email / RSS；不超过 4 个。
- 可选“现在”小节：最近在做什么（3–5 条）。
- 不放技能进度条、时间线装饰、客户 Logo 墙。

### 4.7 搜索 `/search/`（P1）

> P0 不做搜索，导航暂不显示搜索入口；以下为 P1 规格。

```text
搜索

[ 输入关键词，例如：Astro、性能、阅读              ]

共 3 条结果

文章标题
……摘要中的命中片段，关键词高亮……
2026.10.18 · #前端
```

- 搜索框 44px，带可见标签（视觉上可隐藏为 `sr-only`，但必须有 `<label>`）。
- 输入后自动搜索（防抖 200ms），不要求按回车；回车也有效。
- 结果按相关度；显示标题、片段、日期、标签。
- 无结果：“没有找到匹配的内容。试试更短的关键词，或浏览归档。”
- 错误/索引未加载：“搜索暂时不可用，请稍后再试。” + 归档链接。
- URL `?q=` 同步；刷新/分享保留查询。
- `noindex`；不进入 sitemap。
- 无 JS：显示提示 + `/archive/` 链接。

### 4.8 404

```text
404

这一页没有内容。

[ 返回首页 ]  [ 浏览文章 ]
```

- 大号 `404` 使用展示字体，但不超过视口。
- 一句解释，不卖萌、不写长文。
- P0 提供两个明确动作；P1 搜索上线后加“搜索”。
- 不自动跳转。

### 4.9 评论组件（后续，不在原型）

> 原型不实现评论。以下规格保留给上线阶段；原型文章页不渲染该区块。

- 默认状态：`讨论` 标题 + 说明 + `[加载评论]` 按钮。
- 点击后：按钮变为“正在加载…”，注入 Giscus；失败显示“评论加载失败，请到 GitHub Discussions 参与讨论。”
- 已加载：显示 Giscus iframe；不再显示按钮。
- 未配置：整段不渲染。
- 可访问性：按钮有明确标签；加载状态用 `aria-live="polite"`；iframe 有 `title`。
- 隐私：按钮旁说明“评论由 GitHub Discussions 提供，点击后加载”。

## 5. 响应式规则

| 断点 | 布局 | 字体/间距 | 导航 | TOC |
|---|---|---|---|---|
| `< 640px` | 单列 | 正文 16px；gutter 24px | `<details>` 菜单 | 折叠 `<details>` |
| `640–1023px` | 单列 | 正文 17px；gutter 32px | 横向导航可换行 | 折叠 |
| `1024–1279px` | 文章 + 右侧 TOC；首页 7/5 | 正文 17px；gutter 32px | 横向导航 | sticky |
| `≥ 1280px` | 容器 1152px 居中 | 同左 | 横向导航 | sticky |

**硬性规则**

- 375px 宽度无横向滚动；代码块/表格在自身容器内滚动。
- 图片 `max-width: 100%; height: auto`；不裁切正文图。
- 触控目标 ≥ 44×44px；相邻目标至少 8px 间距。
- 不隐藏内容来适配移动端；只改变排列。
- 200% 缩放时导航可换行，不出现内容重叠。
- 粘性 Header 不遮挡锚点：`scroll-padding-top: 80px`。

## 6. 交互与状态

| 元素 | 默认 | 悬停 | 焦点 | 激活/当前 | 禁用/空 |
|---|---|---|---|---|---|
| 正文链接 | 粉色下划线 1px | 颜色变深，下划线 2px | 2px 焦点环 | — | — |
| 导航链接 | `--fg-muted`，无下划线 | `--fg` | 焦点环 | 2px 粉色下划线 + `aria-current` | — |
| 主按钮 | 粉底黑字 | 更亮粉底 | 焦点环 | 按下轻微变暗（不改布局） | 50% 透明，`not-allowed` |
| 标签 | 1px 边框，muted | `--fg` + 强边框 | 焦点环 | — | 无文章标签不生成 |
| 主题切换 | 图标按钮 44px | `--surface-muted` | 焦点环 | `aria-pressed` 反映暗色 | — |
| 分页 | 数字/箭头 | 背景 muted | 焦点环 | 当前页加粗 + 粉色下划线 | 首/尾页禁用箭头 |
| 代码复制 | 图标 + “复制” | 背景 muted | 焦点环 | 2 秒“已复制” | 失败“复制失败” |
| 搜索（P1） | 空输入 | — | 焦点环 | 加载中/结果/空/错误 | 无 JS 提示 |
| 评论（后续） | 加载按钮 | 背景 muted | 焦点环 | 加载中/已加载/失败 | 未配置则隐藏 |
| TOC | muted | `--fg` | 焦点环 | 当前项粉色 + 左边框 | 少于 3 项隐藏 |

**状态文案**

- 加载中：`正在加载…`（省略号用 `…`，不用三个点）。
- 空：`这里还没有内容。`
- 错误：`出了点问题。请刷新页面，或稍后再试。`
- 成功复制：`已复制`
- 复制失败：`复制失败`

**动效**

- 颜色/边框/下划线：120ms `--ease-out`。
- 移动菜单（以及 P1 搜索面板）：180ms；只改变 `opacity`/`transform: translateY(-4px)`，不改变布局。
- 无页面进入动画、无滚动动画、无视差。
- `prefers-reduced-motion: reduce` 下全部关闭。

## 7. 可访问性

目标 **WCAG 2.2 AA**，实现要求见设计系统 §10 与架构 §12。页面级补充：

- **焦点顺序：** 跳过链接 → Header 导航 → 主题切换 → 主内容 → TOC → 文末导航（评论后续）。
- **跳过链接：** 视觉隐藏，聚焦时显示在左上角，指向 `#main`。
- **标题：** 每页一个 H1；列表页 H2 用于年份/分组；卡片标题用 H3 或链接文本，不滥用标题。
- **链接文本：** 避免“点击这里”；用“阅读《标题》”“查看全部文章”。
- **图标：** 装饰性 `aria-hidden="true"`；独立按钮有 `aria-label`。
- **主题切换：** 按钮标签随状态变化（`切换到暗色模式` / `切换到浅色模式`），并设置 `aria-pressed`。
- **移动菜单：** `<summary>` 可键盘操作；展开后焦点不强制移动；链接可 Tab。
- **TOC：** `<nav aria-label="本文目录">`；当前项 `aria-current="location"`。
- **代码复制：** 结果通过 `aria-live="polite"` 播报。
- **表格：** 有 `<caption>` 或前置说明；表头 `<th scope="col">`。
- **图片：** 内容图必须有意义的 `alt`；截图说明“界面截图：……”；装饰图空 alt。
- **语言：** 页面 `lang="zh-CN"`；英文长引用可加 `lang="en"`。
- **颜色：** 不用颜色单独传达状态；错误/成功同时有文字。
- **动效：** 尊重 `prefers-reduced-motion`；不自动播放。
- **缩放：** 200% 下不丢内容、不重叠；`forced-colors` 下边框/焦点可见。

## 8. 内容设计

### 8.1 语气

- 第一人称，具体、克制、可验证；少用“赋能”“闭环”“颠覆”等词。
- 技术文章先给结论/背景，再展开；生活文章可以松弛，但不堆砌情绪。
- 标题具体，不用标题党；摘要说清楚“这篇解决什么问题/记录什么”。

### 8.2 长度与格式

| 项 | 建议 |
|---|---|
| 标题 | 中文 ≤ 40 字；英文 ≤ 80 字符 |
| 摘要 | 60–160 字；必须能独立成立 |
| 标签 | 1–3 个；来自注册表 |
| 正文 | 段落 2–5 句；H2 每 300–600 字一个 |
| 代码 | 必须标注语言；长代码折叠/分段；不出现密钥 |
| 图片 | 宽度 ≥ 1200px；有 `alt`；截图加说明 |
| 日期 | 显示 `2026.10.18`；`datetime` 用 ISO |
| 阅读时间 | `约 8 分钟`；< 1 分钟显示 `1 分钟` |

### 8.3 中文排版

- 使用中文标点：，。！？；：、“”‘’——《》。
- 中英文之间留一个半角空格（写作时手动控制，不用 CSS 自动加）。
- 数字与单位之间留空格：`4 KB`、`200 ms`、`16 px`；百分号不留：`95%`。
- 不滥用加粗；一段最多一个加粗重点。
- 列表项保持平行结构；句末标点统一。
- 代码内注释可用中文，但标识符用英文。

### 8.4 Frontmatter 示例

```yaml
---
title: 用 Astro 构建一个只读的个人博客
description: 从内容集合、静态路由到 Pagefind 搜索，记录一次以“可维护”为目标的博客重构。
pubDate: 2026-10-18
updatedDate: 2026-10-20
tags:
  - 前端
  - 工程实践
slug: astro-personal-blog
cover: ./cover.jpg
coverAlt: 编辑器中的 Astro 项目结构与构建输出
series:
  name: 个人博客重构
  order: 1
---
```

- 日期不加引号也可以，但全站统一 `YYYY-MM-DD`；按站点时区 `Asia/Shanghai` 的日历日解释与显示（`Intl.DateTimeFormat` 固定 `timeZone`）。
- 需要精确到时刻的定时发布，使用带偏移的 ISO 时间，如 `2026-10-18T09:00:00+08:00`。
- `tags` 用中文显示名；构建时映射到 ASCII slug。
- `coverAlt` 与 `cover` 同时出现；否则构建失败。

## 9. 视觉验收

### 9.1 视口

- [ ] 375×812（iPhone SE/13 mini 级别）
- [ ] 768×1024（平板竖屏）
- [ ] 1024×768（小桌面/平板横屏）
- [ ] 1440×900（桌面）
- [ ] 200% 浏览器缩放

### 9.2 内容压力测试

- [ ] 超长标题（中文 40 字/英文 80 字符）不溢出、不遮挡。
- [ ] 无摘要、无标签、无封面、无目录的文章。
- [ ] 超长标签（英文 20 字符/中文 8 字）在列表中换行。
- [ ] 宽代码块（> 100 字符）横向滚动，不撑破页面。
- [ ] 宽表格（8 列）横向滚动。
- [ ] 图片缺失/加载失败时保留尺寸与 alt 文本。
- [ ] 只有 1 篇文章时的首页/列表/分页。
- [ ] 0 篇文章时的空状态。
- [ ] 深色模式下代码高亮仍可读。

### 9.3 状态

- [ ] Light / Dark / 跟随系统；刷新无闪烁。
- [ ] 键盘焦点在浅色/深色背景都清晰。
- [ ] 移动菜单展开/关闭；TOC 展开/关闭。
- [ ] 搜索（P1）：空、加载、有结果、无结果、错误。
- [ ] 评论（后续）：未配置、未加载、加载中、已加载、失败。
- [ ] 复制：成功、失败。
- [ ] 404 页面。

### 9.4 质量检查

- [ ] Lighthouse 移动端手工跑一次：记录 Performance/A11y/BP/SEO；不作为原型门禁。
- [ ] axe：无 serious/critical（原型门禁）。
- [ ] 无横向滚动；无布局位移（CLS < 0.05）。
- [ ] 无 emoji 图标；无 Google Fonts 运行时请求。
- [ ] 所有交互目标 ≥ 44×44px。
- [ ] 所有图片有 alt；所有表单有标签。
- [ ] 未引入部署、评论、分析相关代码或配置。
